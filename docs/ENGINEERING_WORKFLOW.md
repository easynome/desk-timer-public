# 从需求到交付：以 desk-timer 为例

2026-10-16，Codex；依据用户希望学习需求分析、测试隔离与回滚的请求。

## 收到需求先确定什么

先确定使用结果，再看实现。比如“减少后台内存”要确认是空闲常驻、计时中还是打开工作台占用；堆上限、Private Bytes 和 Working Set 各自回答的问题不同。不能只把 Xmx 调低就宣布优化完成。

接着读现状与边界：入口、数据流、数据库迁移、导出契约、已有测试、当前运行版本。源码已完成不等于用户安装版已升级；本次就是源码 v1.2 已验收而日常仍为 v1.1。

把需求转成可检查的条件。例如强制休息：累计满 90 分钟触发、暂停工作、覆盖每个显示器、普通跳过不可用、提前退出不清零、重启不抹掉累计。再问哪些判断只是启发式：无输入不一定离席，阅读/视频也可能是持续使用。记录这种边界，避免把产品判断说成客观事实。

排优先级时先修会丢数据、重复记时或部分成功的缺陷，再增加界面功能。UI 从持久层读取事实；计时器写真实时间，打卡侧读取导出并判断学习证据，不能凭时长自动认定学习任务完成。

## 怎么实现与验证

做一条能贯通的最小链路：例如任务→番茄→提醒→休息→时间线→导出；不要一次重写整个架构。把事务和状态规则放在可独立验证的位置，界面负责展示与用户动作。只给需要防止回归的行为写测试，不给文案替换凑测试数量。

测试分层：纯逻辑测试检查边界；临时 SQLite 检查事务；隔离 TIMER_HOME 验证 JavaFX 与系统能力；打包运行时验证缺 DLL、资源路径、启动参数等开发环境发现不了的问题；最后检查日常安装与消费侧契约。

失败路径比正常按钮更值得测试。本项目实际用 SQLite trigger 注入标签/待办关联写入失败，断言主记录、标签、关联、回执一起回滚；然后重试只产生一条记录。也让文件台账写入失败，再证明数据库幂等回执仍阻止重复计时。

通过只能证明已覆盖的范围：模拟 90 分钟阈值不等于完成了真实 90 分钟观察；音频设备启动不等于人工确认听感；短时内存采样不等于长期没有泄漏。验收记录必须写明这些差异。

## 回滚分四种，不是一条 Git 命令

| 对象 | 本项目方法 | 能恢复什么 | 不能恢复什么 |
|---|---|---|---|
| 失败的测试 | 临时目录/独立 TIMER_HOME；修复后用新夹具重跑 | 隔离副作用，真实记录不受污染 | 不能证明生产环境不会出错 |
| 单次业务写入 | SQLite transaction、失败注入、幂等回执 | 同一操作同成同败，重试不重复 | 不能撤销已提交后发生的外部操作 |
| 源码 | 小步 commit；已共享提交优先 git revert | 生成反向变更，保留审计历史 | 不会替换正在运行的程序或恢复数据库 |
| 安装与数据 | 整套旧安装目录、停止写入后的完整数据快照、哈希与恢复演练 | 回到旧二进制和对应旧数据状态 | 恢复旧数据会舍弃快照后的真实新增记录 |

`git pull` 是拉取并整合远端提交，不是回滚命令。`git revert <commit>` 生成一个抵消指定提交的新提交，仍需测试、构建、部署。参见 [Git pull](https://git-scm.com/docs/git-pull)、[Git revert](https://git-scm.com/docs/git-revert)。不要把重写共享历史的 reset/force-push 当日常恢复方式。

```powershell
git status
git log --oneline -5
# 以下仅示意：先确认提交与工作区，再执行，不把尖括号占位符原样运行。
git revert <需要撤销的提交>
mvn -B test
# 重新构建并验收安装包，然后部署；git push 只同步源码。
```

SQLite WAL 模式不能只复制主库。应用运行时备份使用 VACUUM INTO；本次升级脚本先终止已授权的安装进程、确认单写者锁释放，再一起保存数据库及残存 WAL、inbox、导出与配置。快照同时保留旧程序，并记录各文件 SHA256。

迁移后不能默认把旧程序接到新库上。先在副本上验证兼容性；不兼容时优先向前修复，或经过明确的数据取舍后恢复对应快照。升级脚本不会因为新版本启动失败就自动把真实数据库倒回过去。

## 这次采用的升级步骤

`tools/install-update.ps1` 先校验已测试 JAR 的预期 SHA256，复制新镜像到安装根目录的 staging 并核对每个文件；随后按完整 exe 路径停止旧实例。取得数据目录锁后保存快照并核对哈希，把旧安装整目录移入 rollback，切换新目录。新进程必须产生新版本 manifest、当前启动成功日志并保持存活，才记 UPGRADE_OK。

没有直接覆盖活动 DLL，也不依据“进程名叫 java”去关闭其他程序。脚本失败会保留已有证据；它不是覆盖所有断电/磁盘故障的自动恢复系统。隔离演练、真实升级回执与剩余限制见对应交付审查记录。

后续优先做规模/长时使用验证，再补正式打卡归档的持久去重和回执。历史编辑、标签管理、CLI 等应由实际使用障碍驱动，不为了功能数量增加后台负担。
